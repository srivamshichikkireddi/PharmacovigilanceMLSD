# Evaluation (L2, L3)

Run from the command line (no network, no model needed):
```bash
python -m pv.eval.run --validate-gold                       # every gold passage exists in the corpus
python -m pv.eval.run --label agentic                       # after
AGENTIC_RETRIEVAL=false python -m pv.eval.run --label single_pass_baseline   # before
```
Results are written to `eval/results/<label>.json` (per-scenario rows + aggregate).

## The set
`eval/scenarios.json`: **26 scenarios** (22 full cases + 4 boundary rejections), regenerated by `scripts/make_scenarios.py`. Each carries the expected outcome and the **gold supporting passages** (source + page + anchor/term), located by scanning the corpus text, independent of the retriever. Coverage: the section 4.1 case (PV-01); every seriousness criterion (death, life-threatening, hospitalisation, disability, congenital anomaly); listed and *unlisted* reactions; non-serious periodic cases; every escalation path (unmatched reaction, generic-only match, drug outside corpus, timing contradiction, narrative/flag conflict, medically-important term without a flag); no-adverse-event `non_reportable`; injection, toxicity, cross-field and type rejections.

**Caveat (say this in the viva).** The labels were assigned by the author from reading the PDFs and the system was written by the same people. Have a second reviewer confirm them. Vamshi confirmed the PV-01 serious-expected route as expedited on 29/10/2026; it rests on how IPC 2.7.1 and the NDCT Fifth Schedule interact (see `docs/LEARN.md`, section 2).

**Evaluation 1 reference answer (human confirmation).** Vamshi confirmed on 29/10/2026 (time not provided) that the serious-expected section 4.1 case routes to `expedited_report`. The IPC/NDCT conflict remains surfaced, and QPPV confirmation is required.

## How each metric is computed
All metrics are deterministic (no LLM judge), so they are free and reproducible. TruLens-style names, computed against gold labels and corpus text:

| Metric | Computation |
|---|---|
| **Groundedness** | Over *answered* cases: share of cited claims whose quote appears verbatim (whitespace-insensitive) in the corpus chunk it cites, **re-read from the index**, not from the run's own state. |
| **Faithfulness** | Over answered cases: share of the answer's assertions (each seriousness criterion, expectedness, 15/90-day timeline) that are *entailed* by a cited quote: the anchor regex must match the quote and the number of days must match the quote's. |
| **Context relevance** | Share of passages the agent retrieved (across all tool calls) that lie on a gold (source, page). |
| **Context recall** | Share of gold (source, page) passages that were retrieved. |
| **Hallucination rate** | Over all valid cases: answered AND (a citation does not resolve OR the route is wrong OR it answered a case that should have been escalated). A confident, unsupported answer. |
| **Unsafe answer rate** | Over cases whose gold outcome is escalation: share the system answered instead. |
| **Escalation-reason accuracy** | When escalation is expected, was it for the expected reason (right answer for the right reason). |

## The deliberate change (L3): single retrieval pass -> agentic retrieval
*Before* is the brief's "straightforward implementation": one search with the reporter's words, then assess. *After* is the agent: term translation, targeted label search, clause lookup, modifier search, derived follow-up query, verification, strategy retry. Same corpus, same verifier, same scenarios, no LLM in either (`LLM_PROVIDER=none`).

| Metric | Before: single pass | After: agentic |
|---|---|---|
| Route accuracy (22 valid cases) | 0.32 | 1.00 |
| Answered (not escalated) | 0.00 | 0.68 |
| Escalation-reason accuracy | 1.00 | 1.00 |
| Seriousness accuracy | 1.00 | 1.00 |
| Expectedness accuracy | 0.40 | 1.00 |
| Groundedness (answered cases) | n/a (nothing answered) | 1.00 |
| Faithfulness (answered cases) | n/a (nothing answered) | 1.00 |
| Context relevance | 0.04 | 0.37 |
| Context recall of gold passages | 0.09 | 0.94 |
| Hallucination rate | 0.00 | 0.00 |
| Unsafe answer rate | 0.00 | 0.00 |
| Mean tool calls / run | 0.86 | 4.77 |

**Reading it honestly.**
* The single-pass system retrieves under 10 % of the gold passages, so it can answer **nothing**; but the verifier makes it *safe*: 0 % hallucination, it escalates everything. This is exactly the brief's section 5 argument, measured: a single search "returns passages resembling the question" and misses the provisions the case turns on.
* Agentic retrieval lifts context recall from about 0.09 to about 0.94 and routes all 22 cases correctly *for the right reasons*.
* **Context relevance stays low** because the agent deliberately over-retrieves (several searches per criterion, `k` up to 8). Precision is the cost of recall here; improving it (smaller `k`, reranking) is listed under next steps.
* Accuracy is high partly because the scenarios were written alongside the system. Treat 22/22 as "the engineering works on the cases we thought of", not as a population estimate.

## Prompt-variant comparison (L2)
Prompt variants are versioned files: `prompts/normalise_v1.txt` (plain) and `prompts/normalise_v2.txt` (role + rules + few-shot, JSON only). Every response records `prompt_versions` (`name@content-hash`). The comparison needs a real model, because with `LLM_PROVIDER=none` the prompts are never used:
```bash
export LLM_PROVIDER=openai_compat LLM_BASE_URL=... LLM_API_KEY=... LLM_MODEL=...
PROMPT_NORMALISE=normalise_v1 python -m pv.eval.run --label prompt_v1
PROMPT_NORMALISE=normalise_v2 python -m pv.eval.run --label prompt_v2
python scripts/compare_runs.py prompt_v1 prompt_v2
```
Report which was better, on which metric, by how much. **Expect small differences on this set**: the glossary and rule plan already reach the right label terms, so the prompt mostly matters for reactions the glossary lacks. Add a few scenarios with unusual lay wording to make the comparison informative, and say so.

## The deliberate fault: self-verification catching an unsupported answer (demo item 6)
`FAULT_INJECTION=fabricated_citation` makes the Assessor, on its first attempt only, add a claim ("reporting window is 7 days") with an invented quote, standing in for a model hallucination. The verifier rejects it (`quote_not_in_passage`), the controller retries with a new strategy, and the second attempt passes. Covered by `tests/test_agent.py::Verification`.

## C6: embedding retrieval and precision tuning

The corpus was indexed with `WITH_EMBEDDINGS=1`, `EMBEDDINGS_ENABLED=true`, and `sentence-transformers/all-MiniLM-L6-v2`. The index contains 1,216 chunks. `/ready` returned `ready=true`, the model, and an empty queue; that snapshot counted two worker registrations, while Compose later showed all three worker containers healthy. A direct vector query returned document IDs and the active retriever reported `hybrid(tfidf+vectors)`.

| Metric | TF-IDF before | Hybrid, equal RRF weights | Hybrid, lexical weight 2 |
|---|---:|---:|---:|
| Route accuracy | 1.0000 | 1.0000 | 1.0000 |
| Context relevance (precision proxy) | 0.3696 | 0.3748 | 0.3788 |
| Context recall | 0.9367 | 0.9667 | 0.9667 |
| Groundedness | — | 1.0000 | 1.0000 |
| Faithfulness | — | 1.0000 | 1.0000 |
| Hallucination rate | 0.0000 | 0.0000 | 0.0000 |
| Unsafe-answer rate | 0.0000 | 0.0000 | 0.0000 |

Doubling the lexical reciprocal-rank contribution increased context relevance by 0.0092 absolute over the TF-IDF baseline while preserving route accuracy and recall above 0.90. A smaller top-k experiment reduced context relevance to 0.3589, so it was discarded. The final result is deterministic on this 26-scenario author-labeled set; the gain is small and should not be read as a population-level estimate.

Incremental behavior was checked on a separate Docker volume and a temporary copy of the corpus. The first run embedded 1,216 chunks; an unchanged rebuild embedded 0; after adding one extractable text page to the copied `tegretol_us_pi.pdf`, only its new chunk was embedded (1 new/changed chunk, 0 removed). The original corpus was not modified. See [`evidence/c6/`](../evidence/c6/).
