# Evaluation (L2, L3)

Run from the command line. Gold validation is offline; provider-backed runs use the configured model:
The evaluator reads process environment variables; unlike Docker Compose, a local `python -m` invocation does not load `.env` automatically. The provider commands below assume configuration is already present in the process environment.
```bash
python -m pv.eval.run --validate-gold                       # every gold passage exists in the corpus
python -m pv.eval.run --label agentic                       # after
python -m pv.eval.run --label single_pass_model_baseline --baseline
```
Results are written to `eval/results/<label>.json` (per-scenario rows + aggregate).

## How each metric is computed
All metrics are deterministic (no LLM judge), so they are free and reproducible. TruLens-style names, computed against gold labels and corpus text:

| Metric | Computation |
|---|---|
| **Groundedness** | Over *answered* cases: share of cited claims whose quote appears verbatim (whitespace-insensitive) in the corpus chunk it cites, **re-read from the index**, not from the run's own state. |
| **Faithfulness** | Over answered cases: share of the answer's assertions (each seriousness criterion, expectedness, 15/90-day timeline) that are *entailed* by a cited quote: the anchor regex must match the quote and the number of days must match the quote's. |
| **Context relevance** | Share of passages the agent retrieved (across all tool calls) that lie on a gold (source, page). |
| **Context recall** | Share of gold (source, page) passages that were retrieved. |
| **Hallucination rate** | Over all valid cases: answered AND (a citation does not resolve OR the route is wrong OR it answered a case that should have been escalated). A confident, unsupported answer. |
| **Unsafe answer rate** | Over cases whose gold outcome is escalation: share the system answered instead. |
| **Escalation-reason accuracy** | When escalation is expected, was it for the expected reason (right answer for the right reason). |

## Prompt-variant comparison (L2)
Prompt variants are versioned files: `prompts/normalise_v1.txt` (plain) and `prompts/normalise_v2.txt` (role + rules + few-shot, JSON only). Every response records `prompt_versions` (`name@content-hash`). The comparison needs a configured model, because with `LLM_PROVIDER=none` the prompts are never used:
```bash
# Set LLM_PROVIDER, LLM_BASE_URL, LLM_API_KEY, and LLM_MODEL in .env.
PROMPT_NORMALISE=normalise_v1 python -m pv.eval.run --label prompt_v1

python scripts/compare_runs.py prompt_v1 prompt_v2
```

## The deliberate fault: self-verification catching an unsupported answer (demo item 6)
`FAULT_INJECTION=fabricated_citation` makes the Assessor, on its first attempt only, add a claim ("reporting window is 7 days") with an invented quote, standing in for a model hallucination. The verifier rejects it (`quote_not_in_passage`), the controller retries with a new strategy, and the second attempt passes. Covered by `tests/test_agent.py::Verification`.

### A3 remediation and live PV-01 result (2026-10-31)

The failed trace showed the root cause: the model repeatedly proposed broad corpus searches without a source or searches for generic terms such as "serious" and "exception." These actions were structurally valid but did not serve the current unmet evidence need, consumed the 12-step limit, and prevented retrieval of the applicable provisions. The earlier client also discarded `finish_reason`, so truncation could not be ruled out from that run; it recorded no timeout/degradation event, and its visible completions were short.

The evidence policy now accepts a proposed action only when its tool arguments address a currently unmet need (including source and reaction-term checks); otherwise it marks the run degraded and follows the deterministic rule plan for that step. Serious cases explicitly require both NDCT exception and PSUR anchors. A completion ending with `finish_reason=length` is recorded and treated as unusable without a retry. If verification does not pass, the API withholds seriousness and expectedness, marks the assessment `unverified`, and retains the QPPV escalation path. A browser check confirmed the client displays the unverified notice and escalation path.

With the provider enabled only for the authorized request (`LLM_MAX_RETRIES=0`, `LLM_MIN_INTERVAL_S=5`, `AGENT_RUN_TIMEOUT_S=180`), the synthetic API request returned **HTTP 202**, run ID `26e6e068272c477b`; polling returned **HTTP 200**, status `done`. The final result was `expedited_report`, serious, expected, with `verification=passed`, five verified citations, five steps/tool calls, and 32.422 seconds run time. The assessment used the deterministic fallback (`degraded=["llm_unusable:action"]`); all five model action proposals were rejected as unscoped or irrelevant, so this run proves the fallback path works, not that the provider selected the executed tools. All seven recorded provider completions had `finish_reason=stop`.

The ordered retrieval path was:

1. `search_label` with skin-exfoliation/exfoliative-dermatitis terms -> `tegretol_us_pi_p0013_c03` (page 13), listing exfoliative dermatitis. This is the medical-term match for the reporter's "skin peeling" wording.
2. `search_corpus` against `ipc_mah_v2` for the hospitalization seriousness criterion -> passages on page 31.
3. `get_clause` for IPC 2.7.1 -> `ipc_mah_v2_p0033_c01` (page 33), the 15-calendar-day serious-event provision.
4. `find_modifiers` on that retrieved timeline passage -> derived query: `authority nra nra cdsco cdsco umc causality unexpected expected periodic safety update`.
5. `search_corpus` against `cdsco_rules` with that exact derived query -> `cdsco_rules_p0229_c01` (page 229), supporting both the serious-unexpected 15-day provision and the PSUR 30-day provision.

The five returned basis items cite: hospitalization seriousness (`ipc_mah_v2`, p.31); listed exfoliative dermatitis (`tegretol_us_pi`, p.13); IPC 2.7.1 (`ipc_mah_v2`, p.33); and the NDCT exception and PSUR provisions (`cdsco_rules`, p.229). The verifier resolved each citation to retrieved text.
